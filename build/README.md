# Сборка страниц статей из Directus

Статьи живут в Directus (коллекция `articles`, принадлежность лендингу — связь `site`).
Скрипт забирает опубликованные статьи своего лендинга и раскладывает их в статические
страницы `articles/index.html` и `articles/<slug>/index.html`. В прод уезжает обычная
статика, браузер в CMS не ходит.

## Запуск

```bash
cp build/.env.example build/.env   # прописать DIRECTUS_URL и DIRECTUS_TOKEN
node build/build-articles.mjs
```

## Переменные (build/.env)

| Переменная | Смысл |
|---|---|
| `DIRECTUS_URL` | адрес Directus: локально `http://localhost:8057`, на проде — домен CMS |
| `DIRECTUS_TOKEN` | статик-токен пользователя `build@example.com` (роль Build, только чтение). **Не коммитить** — он видит и черновики |
| `SITE_KEY` | ключ лендинга в коллекции `sites` |
| `DEPLOY_CMD` | команда выкладки после сборки. Пусто — только генерация файлов |

## Что делает сборка

- берёт только `status = published` своего лендинга;
- фолбэки: `seo_title → title`, `meta_description → excerpt`, `og_* → seo`, `twitter_* → og`;
- canonical: значение из CMS, иначе `base_url + /articles/<slug>/`;
- генерит `BlogPosting` и `BreadcrumbList`, ручной JSON-LD из поля `jsonld` выводит как есть
  (невалидный JSON пропускается);
- таблицы из редактора оборачивает в `.table-wrap`, картинкам в теле ставит `loading="lazy"`;
- картинки тянет через трансформы Directus (`format=webp`) в `assets/articles/`;
- похожие статьи: ручной выбор из CMS, добор до трёх — по категории;
- обновляет блок статей в `sitemap.xml` (см. ниже);
- подчищает за собой, см. ниже.

Шаблоны — `build/render.js`, стили — `article.css` в корне поверх общего `styles.css`.
Файлы `build/build-articles.mjs`, `build/render.js` и `article.css` одинаковы во всех
лендингах: различается только `SITE_KEY`. Правку шаблона нужно разнести по всем копиям.

## Автопересборка

Правка в админке подхватывается сама: Directus шлёт вебхук, сервис пересобирает страницы.
Сервис общий на все лендинги и живёт в `game-directus/rebuild-server.mjs` — там же
инструкция и systemd-юнит.

```bash
cd ../game-directus && node rebuild-server.mjs
curl localhost:8790/status
```

Точечно пересобрать только этот лендинг: `POST /rebuild?site=<SITE_KEY>` с заголовком
`x-rebuild-secret`.

## Весь текст — из админки

В шаблонах нет захардкоженного контента: шапка, меню, кнопка, футер, плашка 18+,
подписи и тексты страницы списка берутся из полей лендинга (коллекция `sites`).

| Группа полей | Что задаёт |
|---|---|
| Шапка и навигация | `logo_image` (+ `logo_image_w/h`) или `logo_icon` + `logo_text`, `nav_links`, `cta_label` / `cta_url` / `cta_rel`, `age_notice` |
| Футер | `footer_copyright`, `footer_badges` |
| Страница списка | `articles_kicker`, `articles_title`, `articles_intro`, `articles_seo_title`, `articles_meta_description`, `articles_empty_text` |
| Подписи | `label_home`, `label_articles`, `label_byline`, `label_updated`, `label_related` |
| Технические | `theme_color`, `favicon_path`, `apple_icon_path`, `analytics_path`, `fonts_url` |

Пустое поле — блок не выводится, подстановок «по умолчанию» в коде нет.
`nav_links` управляет шапкой, мобильным меню и футером: внутренние ссылки пишутся
относительно корня (`chicken-road-demo/`), якоря — как `#rtp`, внешние — полным `https://`.
Поле `key` со значением `articles` подсвечивает активный пункт.

## Что удаляется при сборке

Сборка сверяет содержимое папок с тем, что реально отдаёт CMS, и убирает лишнее:

| Что | Когда исчезает |
|---|---|
| `articles/<slug>/` | статью удалили, сняли с публикации или сменили ей слаг |
| `assets/articles/*.webp` | на картинку больше не ссылается ни одна страница |
| строка в `sitemap.xml` | статьи нет в выдаче либо у неё стоит `noindex` |

Удаление идёт только внутри `articles/` и `assets/articles/` — это выходные папки
сборки. Исходники лендинга лежат в `assets/` уровнем выше, туда скрипт не заходит.

Через вебхук это происходит само: удалили статью в админке — через ~15 секунд её
страница и картинки пропали из рабочего дерева. Файлы под git, поэтому в `git status`
они будут висеть как удалённые до коммита — коммитить сборка ничего не будет.

Картинка при этом остаётся в медиатеке Directus: файл может использоваться другой
статьёй, поэтому CMS его не трогает. Чистить медиатеку — вручную.

## sitemap.xml

Статьи попадают в карту сайта сами: сборка правит участок между маркерами

```xml
  <!-- articles:start — генерируется build/build-articles.mjs, руками не править -->
  ...
  <!-- articles:end -->
```

Всё, что вне маркеров, остаётся нетронутым — свои страницы лендинга, локали и
hreflang сборка не трогает и файл целиком не перегенерирует. Стиль разметки
подхватывается из файла: где `<url>` пишется в одну строку, туда так и пишется;
`<image:image>` добавляется только если в `<urlset>` объявлено `xmlns:image`.

В карту идут страница списка и все опубликованные статьи, **кроме помеченных
`noindex`** — такая статья остаётся на сайте, но из sitemap исчезает. Снятая с
публикации или удалённая статья пропадает и оттуда, и из файлов.
`lastmod` берётся из `date_updated`, иначе из даты публикации.

Если `sitemap.xml` в лендинге нет, сборка его не создаёт — только предупреждает.
Если в файле нет `</urlset>`, сборка падает с ошибкой, а не портит файл.

## Чего здесь пока нет

Страниц категорий и hreflang между языковыми версиями — делается отдельно,
когда появятся соответствующие страницы.
